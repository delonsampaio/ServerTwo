# Post-Match Quick Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a player record a match that already happened — phone was in their bag during play — by entering each game's final score directly on `MatchSetupView`, instead of the only option today (live, point-by-point tapping through `ScoringView`).

**Architecture:** Extract a pure, reusable `isCompletedGameScore` rule into `GameConfiguration` so both live play's `PickleballGame.gameWinner` and a new `MatchRepository.saveQuickLoggedMatch` share one source of truth for "is this a legal completed game score." `MatchSetupView` gains a secondary "Log Final Score Instead" action that opens a sheet with a fixed-size array of per-game score rows, committing validation only when a field loses focus (never per-keystroke), and writes straight to SwiftData on save — bypassing `PickleballMatch`/`ActiveMatchController` entirely, since there's no live match to drive.

**Tech Stack:** Swift, SwiftUI, SwiftData, XCTest, XCUITest. PickleballKit (local Swift package) holds the engine + persistence; ServerTwo (the app target) holds the UI.

**Spec:** `docs/superpowers/specs/2026-10-14-quick-log-design.md`

## Global Constraints

- No SwiftData schema changes — `GameRecord.points` stays empty and `GameRecord.completedAt` stays `nil` for every quick-logged game; no new fields.
- Validation commits only when a field loses focus (via `onSubmit` or a focus change), never reactively on every keystroke — a naive live-validator would misread "1" of "13" as a complete score.
- `quickLogEntries` is a fixed-size array, populated once when the sheet opens and never resized afterward — only its elements' text ever mutates, via normal index-based `Binding`, which is only safe because the array's length never changes after creation.
- Row visibility is a pure function of the match's own committed-and-valid scores so far, recomputed on every commit — never a destructive truncation of `quickLogEntries` itself. Typed-but-hidden text is always preserved underneath.
- Quick Log bypasses `PickleballMatch`/`ActiveMatchController`'s match lifecycle entirely, but **not** `activeMatchController.canStartNewMatch` — the same paywall gate "Start Match" already has.
- A blank team name falls back to "Team A"/"Team B" at Quick Log's own save point — same wording as `PendingMatchSetup.resolvedTeamAName`/`resolvedTeamBName`, just invoked directly since Quick Log never creates a `PendingMatchSetup`.
- `.rally(freeze: true)`'s "won while serving" rule and its unconstrained overtime margin are deliberately **not** validated by Quick Log — documented as a Non-goal, not an oversight.
- After a successful save, `MatchSetupView` resets its own name/selection `@State` back to blank — there is no natural view teardown to rely on, since the sheet never leaves this view.
- Every `xcodebuild test` invocation uses `-maximum-concurrent-test-simulator-destinations 2` (never higher — a past run at 4 caused a 30-minute hang). `PickleballKit` itself is tested via `swift test` (run from inside `PickleballKit/`), no simulator involved.
- Authoritative pass/fail verification is `xcrun xcresulttool get test-results summary --path <xcresult>` (and `get test-results tests` for failure detail), piped through `python3` — never raw log greps or SourceKit diagnostics, which have a confirmed false-positive history in this project.
- This Xcode target uses file-system-synchronized groups — new Swift files need no `project.pbxproj` edit to be picked up.

## Review Focus

- Typing a 2-digit score mid-keystroke (e.g. the "1" of "13") must never be momentarily treated as a committed, valid, game-deciding score — a later row must not flash into existence and then disappear before the second digit lands. (Task 4)
- Editing an already-committed row to an invalid or no-longer-decided value must hide (not discard) any now-unreachable later rows' visibility, while the text already typed into those later rows is still there, unchanged, if the earlier row is corrected back. (Task 4)
- A trailing game score entered after the match is already mathematically decided (e.g. typing a 3rd game's score into a Best-of-3 already won 2-0) must be rejected by `saveQuickLoggedMatch`, not silently accepted and allowed to inflate `gamesWon` past `matchFormat.gamesToWin`. (Task 2)
- `correctScore`'s now-tightened validation (via the shared `isCompletedGameScore` rule) must reject a live score correction to a mathematically impossible overtime margin (e.g. 15-10 in an 11-point win-by-2 game) instead of silently accepting it as a completed game — this is a deliberate, real behavior change from today, not a no-op refactor, and the spec calls it out explicitly. (Task 1)
- A quick-logged match's duration badge must not render "< 1 min" when `startedAt == completedAt` exactly (which reads as "this took under a minute" — a bug, not "we don't know") — but a genuinely short *live* match lasting a few real seconds must still show "< 1 min", not disappear too. (Task 3)

```swift
    /// Whether `teamA`/`teamB` represents a legal *completed* game's final
    /// score under this configuration's win condition — not merely "the
    /// win-by-2/winning-score thresholds are currently satisfied" (which
    /// live play never needs to distinguish from "and could only have
    /// gotten here through a legal sequence of single points," since
    /// `PickleballGame.recordPoint` physically cannot overshoot). An
    /// after-the-fact score entry (Quick Log) has no such guarantee, so this
    /// also rejects negative scores and impossible overtime margins (e.g.
    /// 15-10 in an 11-point win-by-2 game — the game would have already
    /// ended at 11-9 or 12-10).
    ///
    /// Deliberately does NOT evaluate `.rally(freeze: true)`'s "won on
    /// serve" rule, or constrain its overtime margin — both depend on live
    /// serve-sequence state this pure score check has no access to.
    /// `PickleballGame.gameWinner` layers the serve-order check on top for
    /// live play; this is for validating an already-known final score with
    /// no serve history (e.g. Quick Log).
    public func isCompletedGameScore(teamA: Int, teamB: Int) -> Bool {
        guard teamA >= 0, teamB >= 0, teamA != teamB else { return false }
        let winner = max(teamA, teamB)
        let loser = min(teamA, teamB)
        guard winner >= winningScore.rawValue else { return false }
        if winByTwo, winner - loser < 2 { return false }
        guard winner > winningScore.rawValue else { return true }  // not overtime — above checks suffice
        if case .rally(let freeze) = scoringFormat, freeze { return true }  // see doc comment
        return winByTwo && (winner - loser == 2)
    }
```

In the same file, add this method immediately after `saveCompletedMatch` ends (after its closing `}` on line 159, before `public func fetchMatchHistory()`):

```swift
    /// A match recorded after the fact from final scores alone, with no
    /// point-by-point log — bypasses `PickleballMatch` entirely since there's
    /// no live match to drive. `gameScores` must be non-empty and its last
    /// entry must decide the match (one team reaching `matchFormat
    /// .gamesToWin`); earlier entries must each be a legal completed game
    /// per `configuration.isCompletedGameScore` — both are caller
    /// responsibilities (the Quick Log UI validates as the user types, this
    /// method trusts that and just asserts via `MatchRepositoryError
    /// .matchNotOver`/`.invalidGameScore` if violated, the same defensive
    /// posture `saveCompletedMatch` already has for `matchNotOver`).
    @discardableResult
    public func saveQuickLoggedMatch(
        configuration: GameConfiguration,
        matchFormat: MatchFormat,
        teamAName: String,
        teamBName: String,
        gameScores: [(teamA: Int, teamB: Int)],
        teamAPlayers: [SavedPlayer] = [],
        teamBPlayers: [SavedPlayer] = [],
        completedAt: Date = Date()
    ) throws -> MatchRecord {
        var gamesWon: [Team: Int] = [.teamA: 0, .teamB: 0]
        var gameRecords: [GameRecord] = []
        for (index, score) in gameScores.enumerated() {
            // A game entry after the match was already decided (e.g. a 3rd
            // game for a Best of 3 that's already 2-0) is as invalid as a
            // bad score — without this, extra trailing entries would
            // silently inflate gamesWon past matchFormat.gamesToWin and
            // still "succeed."
            guard gamesWon[.teamA, default: 0] < matchFormat.gamesToWin,
                  gamesWon[.teamB, default: 0] < matchFormat.gamesToWin else {
                throw MatchRepositoryError.invalidGameScore
            }
            guard configuration.isCompletedGameScore(teamA: score.teamA, teamB: score.teamB) else {
                throw MatchRepositoryError.invalidGameScore
            }
            let winner: Team = score.teamA > score.teamB ? .teamA : .teamB
            gamesWon[winner, default: 0] += 1
            let gameRecord = GameRecord(
                gameNumber: index + 1,
                teamAFinalScore: score.teamA,
                teamBFinalScore: score.teamB,
                winningTeam: winner
            )
            // gameRecord.points and .completedAt both left at their defaults
            // (empty array, nil) — no point log and no per-game timing data
            // exist for a quick-logged game.
            gameRecords.append(gameRecord)
        }
        guard let matchWinner = (
            gamesWon[.teamA, default: 0] >= matchFormat.gamesToWin ? Team.teamA :
            gamesWon[.teamB, default: 0] >= matchFormat.gamesToWin ? Team.teamB : nil
        ) else {
            throw MatchRepositoryError.matchNotOver
        }

        let configurationData = try JSONEncoder().encode(configuration)
        let record = MatchRecord(
            startedAt: completedAt,
            completedAt: completedAt,
            matchFormat: matchFormat,
            winningTeam: matchWinner,
            configurationData: configurationData
        )
        // Same explicit-insert-for-every-object discipline as
        // saveCompletedMatch, for the same reason (see its own comment).
        modelContext.insert(record)

        let teamASide = TeamSide(team: .teamA, displayName: teamAName)
        let teamBSide = TeamSide(team: .teamB, displayName: teamBName)
        teamASide.match = record
        teamBSide.match = record
        teamASide.players = teamAPlayers
        teamBSide.players = teamBPlayers
        record.teamSides = [teamASide, teamBSide]
        modelContext.insert(teamASide)
        modelContext.insert(teamBSide)

        for gameRecord in gameRecords {
            gameRecord.match = record
            modelContext.insert(gameRecord)
        }
        record.games = gameRecords

        try modelContext.save()

        return record
    }
```

    /// format could ever need (1 for Best of 1, 3 for Best of 3, 5 for Best
    /// of 5) — populated fresh every time the sheet opens, and never
    /// resized afterward; see Global Constraints.
    private func presentQuickLogSheet() {
        quickLogEntries = (1...((matchFormat.gamesToWin * 2) - 1)).map { QuickLogGameEntry(id: $0) }
        quickLogCommittedScores = []
        quickLogIsDecided = false

    /// Re-derives the committed, valid scores (and whether the match is
    /// decided) from quickLogEntries' current text — called only when a
    /// field commits (loses focus), never on every keystroke. Stops at the
    /// first row that isn't both parseable and a legal completed game under
    /// the current rules, or once a team has already reached
    /// matchFormat.gamesToWin — later rows (even with typed text) never
    /// contribute, but their text is untouched either way.
    private func commitQuickLogRow() {
        let configuration = quickLogConfiguration
        var scores: [(teamA: Int, teamB: Int)] = []
        var gamesWon: [Team: Int] = [.teamA: 0, .teamB: 0]
        for entry in quickLogEntries {
            guard gamesWon[.teamA, default: 0] < matchFormat.gamesToWin,
                  gamesWon[.teamB, default: 0] < matchFormat.gamesToWin else { break }
            guard let teamA = Int(entry.teamAText.trimmingCharacters(in: .whitespaces)),
                  let teamB = Int(entry.teamBText.trimmingCharacters(in: .whitespaces)),
                  configuration.isCompletedGameScore(teamA: teamA, teamB: teamB) else { break }
            let winner: Team = teamA > teamB ? .teamA : .teamB
            gamesWon[winner, default: 0] += 1
            scores.append((teamA: teamA, teamB: teamB))

/// quickLogEntries array by index — safe specifically because that array's
/// length never changes after the sheet opens (see Global Constraints).
/// Live typing always writes straight into `entry.teamAText`/`teamBText`

/// while the row itself is temporarily hidden — only `onCommit` (fired on
/// losing focus, never per-keystroke) triggers MatchSetupView to
/// re-validate and recompute which rows should be visible.
private struct QuickLogRow: View {
    @Binding var entry: MatchSetupView.QuickLogGameEntry
    let onCommit: () -> Void

    private enum Field: Hashable { case teamA, teamB }
    @FocusState private var focusedField: Field?

    var body: some View {
        HStack {
            Text("Game \(entry.id)")
                .font(.caption.weight(.semibold))
                .foregroundStyle(.secondary)
                .frame(width: 56, alignment: .leading)

                .keyboardType(.numberPad)
                .multilineTextAlignment(.center)
                .focused($focusedField, equals: .teamA)
                .accessibilityIdentifier("QuickLog.Game\(entry.id).TeamAScore")
            Text("–")
                .foregroundStyle(.secondary)
            TextField("0", text: $entry.teamBText)
                .keyboardType(.numberPad)
                .multilineTextAlignment(.center)
                .focused($focusedField, equals: .teamB)
                .accessibilityIdentifier("QuickLog.Game\(entry.id).TeamBScore")

        // to the other field in this row, moving to a different row
        // entirely, or dismissing the keyboard) is the only reliable commit
